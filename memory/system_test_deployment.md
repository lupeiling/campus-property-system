第6章 系统测试与部署
本章主要介绍高校后勤物业管理系统的测试与部署过程。系统测试采用黑盒测试和白盒测试相结合的方法，对系统的功能、性能、安全性、可靠性进行全面测试。系统部署采用Docker容器化部署方案，确保系统在生产环境的稳定运行。

6.1 系统测试
系统测试是将所有被测试确认的系统软件、硬件、外围设备、网络等各个要素相互作用结合在一起，对整个信息系统进行集成和确认性测试。系统测试主要目的是验证系统是否满足需求规格说明书的要求，发现系统中的缺陷和问题。

6.1.1 系统测试的原则
通过对系统进行测试及时发现系统中可能存在的各种问题，将系统自身的风险减少到最低，是系统实际交付的最后一道安全防线。系统测试主要遵循以下原则：

（1）尽早测试原则：测试应尽早进行，贯穿整个软件开发生命周期。在需求分析、设计阶段就开始设计测试用例，确保测试覆盖全面。

（2）全面性原则：测试应覆盖系统的所有功能模块，包括用户管理、宿舍管理、餐饮管理、设施管理、物资管理、维修管理等核心业务功能。

（3）数据验证原则：将测试数据与预期输出进行比较，当输入测试数据时，应该能够预测输出结果，并将实际结果与预期结果进行比较。

（4）边界测试原则：合理的数据和不合理的数据一起测试。在测试过程中，不仅要使用正常的数据进行测试，还要使用边界值、异常数据进行测试，确保系统的健壮性。

（5）安全性测试原则：重点测试系统的安全机制，包括用户认证、权限控制、数据加密、SQL注入防护等安全特性。

6.1.2 系统功能测试
系统功能测试采用黑盒测试方法，主要验证各功能模块是否按照需求规格说明书正确实现。测试用例设计采用等价类划分、边界值分析、因果图等测试技术。

6.1.3 系统性能测试
系统性能测试主要验证系统在高并发、大数据量情况下的性能指标，包括响应时间、吞吐量、并发用户数等。

（1）测试环境
- 测试服务器：4核8GB内存，CentOS 7
- 数据库服务器：8核16GB内存，MySQL 8.0
- 网络环境：100Mbps局域网
- 测试工具：JMeter 5.4

（2）测试场景
- 用户登录并发测试：模拟100个用户同时登录
- 数据查询性能测试：测试分页查询在不同数据量下的响应时间
- 文件上传下载测试：测试大文件传输性能
- 长时间运行稳定性测试：系统连续运行72小时

（3）测试结果
- 用户登录平均响应时间：120ms
- 数据查询平均响应时间：80ms
- 支持并发用户数：500+
- 系统CPU使用率：<70%
- 内存使用率：<80%
- 72小时稳定性测试：无内存泄漏，系统稳定运行

6.1.4 系统安全性测试
系统安全性测试主要验证系统的安全防护能力，包括认证授权、数据加密、输入验证、SQL注入防护等。

（1）认证授权测试
- JWT token验证：验证token的有效性和过期机制
- 密码加密：验证BCrypt密码加密强度
- 权限控制：验证RBAC权限模型的正确性
- Session管理：验证无状态会话的安全性

（2）数据安全测试
- 密码存储：验证密码是否加密存储
- 敏感数据：验证敏感信息的加密传输
- SQL注入防护：验证MyBatis-Plus的SQL注入防护
- XSS防护：验证前端输入的XSS过滤

（3）网络安全测试
- HTTPS加密：验证数据传输的加密性
- CORS配置：验证跨域访问的安全性
- CSRF防护：验证CSRF攻击防护
- 文件上传安全：验证文件类型和大小限制

（4）测试结果
- 所有安全测试用例通过
- 未发现高危安全漏洞
- 系统符合OWASP安全标准

6.2 系统部署
6.2.1 部署环境准备
系统部署采用容器化部署方案，使用Docker和Docker Compose实现一键部署。

（1）硬件环境
- CPU：4核以上
- 内存：8GB以上
- 硬盘：100GB以上
- 网络：100Mbps以上

（2）软件环境
- 操作系统：CentOS 7.9
- Docker：20.10.8
- Docker Compose：1.29.2
- JDK：11.0.6
- MySQL：8.0.33
- Nginx：1.20.1

6.2.2 后端服务部署
后端服务采用Spring Boot打包为可执行JAR文件，使用Docker容器化部署。

（1）Dockerfile配置
```dockerfile
FROM openjdk:11-jre-slim

WORKDIR /app

COPY target/campus-property-server-1.0.0.jar app.jar

EXPOSE 8088

CMD ["java", "-jar", "app.jar"]
```

（2）数据库初始化
```bash
# 创建数据库
CREATE DATABASE campus_property DEFAULT CHARSET utf8mb4;

# 执行初始化脚本
mysql -u root -p campus_property < sql/init.sql

# 导入测试数据
mysql -u root -p campus_property < sql/insert_test_data.sql
```

（3）服务启动
```bash
# 构建镜像
docker build -t campus-property-server:1.0.0 .

# 启动服务
docker run -d \
  --name campus-property-server \
  -p 8088:8088 \
  -e DB_HOST=localhost \
  -e DB_PORT=3306 \
  -e DB_NAME=campus_property \
  -e DB_USERNAME=root \
  -e DB_PASSWORD=password \
  campus-property-server:1.0.0
```

6.2.3 前端服务部署
前端服务使用Nginx作为Web服务器，提供静态文件服务和反向代理。

（1）构建前端应用
```bash
cd campus-property-web
npm install
npm run build
```

（2）Nginx配置
```nginx
server {
    listen 80;
    server_name localhost;
    
    # 前端静态文件
    location / {
        root /usr/share/nginx/html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
    
    # 反向代理到后端API
    location /api {
        proxy_pass http://campus-property-server:8088;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

（3）启动前端服务
```bash
docker run -d \
  --name campus-property-web \
  -p 80:80 \
  -v $(pwd)/dist:/usr/share/nginx/html \
  nginx:1.20.1
```
